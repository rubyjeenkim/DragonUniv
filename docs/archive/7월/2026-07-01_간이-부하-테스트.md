# Dragon University API 간이 부하 테스트

| 항목 | 내용 |
|---|---|
| 실행일 | 2026-07-01 |
| 목적 | 배포 성능 한계 측정 전, API와 DB 연결의 기본 안정성 확인 |
| 실행 환경 | macOS Docker Desktop 로컬 재현 환경 |
| Backend | Node.js 22 / Express Docker container |
| Database | MariaDB 11.4 Docker container |
| 대상 | `GET /api/health` |
| 도구 | `scripts/simple-load-test.sh` (`curl` + `xargs`) |

## 테스트 범위

`/api/health`는 요청마다 MariaDB에 `SELECT 1`을 실행한다. 따라서 이번 테스트는 HTTP 응답뿐 아니라 Backend → MariaDB 연결도 함께 확인한다.

이 결과는 k3s 또는 실제 운영 환경의 최대 처리량을 측정한 벤치마크가 아니다. 개발 PC 한 대에서 Backend와 MariaDB를 Docker로 실행한 **기본 안정성 확인용 간이 테스트**다.

## 실행 결과

| 단계 | 총 요청 | 동시 요청 | HTTP 200 | 실패 | 평균 | 최소 | 최대 | 전체 시간 | 근사 처리량 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 100 | 10 | 100 | 0 | 6.4ms | 1.3ms | 33.4ms | 0.25s | 약 400 req/s |
| 2 | 1,000 | 50 | 1,000 | 0 | 4.2ms | 1.2ms | 15.0ms | 1.70s | 약 588 req/s |
| 3 | 5,000 | 100 | 5,000 | 0 | 3.3ms | 1.1ms | 42.4ms | 8.32s | 약 601 req/s |

근사 처리량은 `총 요청 / 전체 실행 시간`으로 계산했다. 실행 시간에는 테스트 클라이언트의 프로세스 생성과 결과 집계 비용이 포함된다.

## 테스트 후 확인

- API health: `{"ok":true,"db":"connected"}`
- Backend container: `running`, `healthy`
- Backend restart count: `0`
- Backend idle memory: `43.91MiB`
- MariaDB idle memory: `120.2MiB`

## 결론

- 동시 요청을 10 → 50 → 100으로 올리는 동안 총 6,100건이 모두 HTTP 200으로 완료됐다.
- 테스트 종료 후에도 Backend와 MariaDB 연결이 정상이고 Backend 재시작은 없었다.
- 로컬 기본 안정성은 확인했지만, k3s 환경의 성능과 확장성을 주장할 수 있는 결과는 아니다.
